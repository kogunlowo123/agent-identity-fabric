# ADR-0004: Signing keys are generated outside Terraform

- Status: Accepted
- Date: 2026-10-14

## Context

Terraform can generate keys (`tls_private_key`), but the private key then
lives in Terraform state, readable by anyone with state access and copied to
every backend snapshot.

## Decision

Terraform provisions the KMS key, the secret store and the access policies.
Signing and audit keys are generated by `python -m identity_fabric.keygen
<kid>`, which writes the private PEM only to stdout so it can be piped into
the secret manager CLI, and the public JWK to stderr for the change record.
The External Secrets Operator syncs secrets named
`agent-identity-fabric-signing-key-<kid>` into the pod.

The database password is generated by Terraform (`random_password`) because
RDS, Flexible Server and Cloud SQL need it at creation; state must therefore
use an encrypted, access-controlled backend.

## Consequences

- Key rotation is a runbook procedure (docs/runbooks/key-rotation.md) rather
  than a `terraform apply`.
